# Dentora — Product Blueprint (Draft v0.1)

**Status:** Planning only — no implementation approved.  
**Product:** Premium dental clinic website + booking engine + admin dashboard.  
**Initial assumption:** One clinic, multiple dentists, one location; architecture should permit future extension, but multi-clinic is out of scope for v1.

## Document map
1. `01-PRODUCT-SCOPE.md` — goals, personas, scope boundaries.
2. `02-USER-JOURNEYS.md` — customer and admin workflows.
3. `03-APPOINTMENT-RULES.md` — availability and state machine.
4. `04-ROLES-PERMISSIONS.md` — permission matrix.
5. `05-DATA-MODEL.md` — conceptual schema.
6. `06-PAGES-UX.md` — sitemap and page requirements.
7. `07-API-CONTRACTS.md` — planned endpoints and validation.
8. `08-NONFUNCTIONAL-SECURITY.md` — security, privacy, accessibility and operations.
9. `09-ROADMAP-ACCEPTANCE.md` — milestones and definition of done.
10. `10-DECISION-LOG.md` — questions to lock before coding.
11. `11-TEST-SCENARIOS.md` — representative end-to-end tests.
12. `12-CONTENT-INVENTORY.md` — real vs placeholder clinic content.

> Planning docs are **working drafts**. No tech choice, scope or behavior becomes final until reviewed and marked accepted in the decision log. These files define future implementation targets; they are not source code.
